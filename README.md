## מילון מונחים

המסמך משתמש בכמה מונחים מעולם החיפוש. כולם מוסברים כאן בשפה של פיתוח ווב, בלי רקע בלמידת מכונה.

### המושגים המרכזיים

**סט הזהב**

רשימה קבועה של חיפושים, ולכל אחד מהם נקבע מראש אילו מוצרים נחשבים תשובה נכונה. בפרויקט יש 30 חיפושים כאלה, בקובץ אחד בתיקיית הטסטים.

זה כמו טסטים אוטומטיים, אבל לאיכות החיפוש ולא לנכונות הקוד. טסט רגיל בודק שהקוד לא נשבר. סט הזהב בודק שהתוצאות עדיין טובות. מריצים אותו אחרי כל שינוי במנוע, ומשווים לפני ואחרי. בלי זה, כל שינוי היה מבוסס על "נראה לי שזה עובד".

**וקטור משמעות**

רשימה של 512 מספרים שמודל של OpenAI מחשב לכל טקסט. טקסטים שהמשמעות שלהם דומה מקבלים מספרים קרובים, גם אם אין להם אף מילה משותפת, ואפילו אם הם בשפות שונות.

אפשר לחשוב על זה כמו על קואורדינטות במפה: כל מוצר הוא נקודה במפה, ומוצרים דומים קרובים זה לזה. בחיפוש מחשבים נקודה גם לשאילתה, ומחפשים את המוצרים שהכי קרובים אליה. ככה "מתנה למישהו שאוהב לבשל" מוצא סירים, בלי שהמילה "סיר" מופיעה בשאילתה.

הווקטורים של המוצרים מחושבים פעם אחת ונשמרים בעמודה במסד. בכל חיפוש מחשבים רק את הווקטור של השאילתה.

**דמיון**

מספר שמודד כמה שני וקטורים קרובים. ככל שהוא גבוה יותר, המשמעות קרובה יותר. בפרויקט הזה ג'יבריש מגיע לכל היותר ל־0.20, וחיפוש אמיתי מתחיל בערך מ־0.38.

בלי מפתח של אופן־איי, החיפוש עובד לפי מילים בלבד.

### הרצה מקומית

```bash
git clone https://github.com/amir-1004/htzone-search.git && cd htzone-search
composer install
cp .env.example .env
./vendor/bin/sail up -d
./vendor/bin/sail artisan key:generate
./vendor/bin/sail artisan migrate --seed
./vendor/bin/sail artisan catalog:embed
npm install && npm run build
```

הסבר לפקודות, לפי הסדר:

- **הגדרות:** אחרי ההעתקה, מוסיפים את המפתח של אופן־איי לקובץ הסביבה.
- **סביבה:** פקודת ההפעלה של סייל מרימה את מייסקיואל ואת פי־אייץ'־פי־מיי־אדמין.
- **קטלוג:** פקודת המיגרציה עם הסידר יוצרת את הטבלאות וטוענת את הקטלוג מתוך הקובץ שסופק.
- **וקטורים:** חישוב וקטור משמעות לכל מוצר. לוקח דקה עד שתיים, ועולה כשני סנט.

כתובות מקומיות:

<div dir="rtl">

| מה | כתובת |
|---|---|
| האתר | http://localhost |
| ניהול המסד | http://localhost:8080 |

</div>

### טעינת הקטלוג

**הסידר**

```
database/seeders/CatalogSeeder.php
```

הסידר קורא את קובץ הקטלוג ומעדכן לפי מק"ט, כך שאפשר להריץ אותו שוב בבטחה: אין שכפולים, ומוצר שהשתנה מתעדכן. כשחסרות עמודות בקובץ, הוא נכשל עם הודעה ברורה.

הוא גם שומר בעמודה נפרדת את התווית האנגלית שמופיעה בכתובת התמונה של כל מוצר. לכל 1000 המוצרים יש תווית כזו, והיא משמשת כשם באנגלית בחיפוש.

**פקודת הווקטורים**

```
php artisan catalog:embed
```

הפקודה מחשבת וקטור משמעות רק למוצרים שהטקסט שלהם השתנה, או כשמודל הווקטורים הוחלף. כשמגיעים למגבלת הקצב של אופן־איי היא ממתינה ומנסה שוב, ואם הספק נופל, החיפוש ממשיך לעבוד לפי מילים.

**מחירים**

בקטלוג שסופק אין עמודת מחיר. לכל מוצר נקבע מחיר המחשה קבוע, בטווח שמתאים לתת־הקטגוריה שלו, והממשק מציין שהמחירים להמחשה. שאלתי על זה במייל, והשאלה הועברה למור.

הטווחים מוגדרים בקובץ:

```
config/catalog.php
```

### פריסה ללארבל קלאוד

כל ההגדרה נעשתה דרך כלי שורת הפקודה הרשמי, כך שאפשר לשחזר אותה:

```bash
composer global require laravel/cloud-cli && cloud auth
cloud deploy htzone-search production
```

פקודות הבנייה:

```
composer install --no-dev
npm ci --audit false
npm run build
php artisan optimize
```

פקודות הפריסה:

```
php artisan migrate --force
php artisan db:seed --force
php artisan catalog:embed || true
```

הסימון בסוף השורה האחרונה נועד לכך שנפילה של אופן־איי לא תכשיל את הפריסה.

משתני הסביבה שהוגדרו הם המפתח של אופן־איי והשפה העברית. פרטי המסד מוזרקים אוטומטית.

אין מפתחות או סיסמאות במאגר: קובץ הסביבה לא נשמר בגיט, וכל ההיסטוריה נסרקה לפני שהמאגר הפך לציבורי.

## איך זה עובד

כל חיפוש עובר בשני ערוצים במקביל, ואחר כך הדירוגים שלהם מתמזגים. לדוגמה, החיפוש "משהו שיעזור לנקות שערות של כלב מהספה":

- **ערוץ המילים:** הטקסט מנורמל. מוסרים ניקוד וגרשיים, אותיות סופיות הופכות לרגילות, ומטופלים תחיליות ורבים. כגיבוי בלבד, גם כתיב מלא מול חסר, כמו טוחן מול טחון. מילון כינויים מתרגם שמות שלא מופיעים בקטלוג, למשל "אייפון" לסמארטפון של Apple. כל מוצר מקבל ציון לפי השדה שבו נמצאה ההתאמה (שם, מותג, קטגוריה או תיאור), ולפי כמה ממילות השאילתה הוא מכסה.
- **ערוץ המשמעות:** וקטור לשאילתה, שנשמר במטמון, מושווה ל־1000 וקטורים שחושבו מראש. נשארים מוצרים מעל סף של 0.30, בטווח של 0.10 מהתוצאה הטובה ביותר, ותמיד לפחות 6 מעל הסף.
- **מסנן עקביות:** מוצר שלא מכיל את כל מילות השאילתה, בין אם נמצא לפי משמעות ובין אם לפי חלק מהמילים, חייב להיות בתת־קטגוריה שהשאילתה עוסקת בה.
- **מיזוג:** שני הדירוגים מתמזגים בשיטה שמתחשבת במיקום של כל מוצר בכל רשימה, ולא בציון שלו. מוצגות עד 60 תוצאות, 12 בכל עמוד.

### שני שדות בתשובה שהממשק נשען עליהם

**שדה ההתאמה**

```
match: "related"
```

כשאף תוצאה לא מכילה את מילות החיפוש וכולן נמצאו לפי משמעות, הממשק מציג "לא מצאנו התאמה מדויקת, אלה המוצרים הקרובים". זה המצב, למשל, בחיפוש "כרטיס טיסה לאילת", וגם בחיפוש של אייפון 16, כי אין דגם 16 בקטלוג.

**שדה הגיבוי**

```
degraded: true
```

כשהחיפוש לפי משמעות היה אמור לרוץ אבל הספק נכשל, הממשק מציג "החיפוש החכם לא זמין כרגע", ולא "לא נמצאו מוצרים".

## החלטות מרכזיות

ההחלטות המלאות, עם המספרים, נמצאות במסמך ההחלטות שבתיקיית התיעוד.

<div dir="rtl">

| החלטה | למה | מה נדחה |
|---|---|---|

## איך עבדתי עם Claude

עבדתי עם Claude Code, במודל Opus 5.5. לפני כל שלב, Claude ראיין אותי על ההחלטות, וכל החלטה עם השלכה על המוצר נשארה אצלי. את מה שהוא עשה, וידאתי באחת משלוש דרכים: טסט, סט הזהב, או בדיקה בדפדפן. היומן המלא נמצא בתיקיית התיעוד.

### איך העבודה הייתה מסודרת

- **מוסכמות:** קובץ ההוראות של הפרויקט מגדיר שאין טקסט בלי תרגום, אין מפתחות במאגר, כל טסט משתמש בתשובות מזויפות לשירותים חיצוניים, ואחרי כל שינוי במנוע מריצים את סט הזהב.
- **שמירות:** כל שלב (תכנון, בנייה, חיפוש, כיול, פריסה וממשק) נשמר בנפרד, עם הודעה בעברית.
- **פריסה:** Claude ביצע את הפריסה דרך כלי שורת הפקודה של לארבל קלאוד. את ההרשאה בדפדפן ואת הגדרת המפתח של אופן־איי עשיתי אני, ו־Claude לא ראה את המפתח.

### הצעה של Claude שנבדקה ונדחתה לפי מספרים

שאלתי אם אפשר לשפר את החיפוש בעזרת הקטגוריות. Claude הציע לחזק מוצרים לפי וקטור ממוצע של תת־הקטגוריה. ביקשתי שיבדוק, ולא ישמור אם זה לא משפר. השיפור היה 2 מוצרים רלוונטיים מתוך כל הסט, בלי אף כישלון שהפך להצלחה, ולכן הקוד הוסר.

אחר כך בדקתי בעצמי כמה חיפושים ("סכינים", "שעון יד", "כלב גדול", "מתנה לאמא טריה") ומצאתי בהם רעש. Claude הוסיף אותם לסט הזהב, ותכנן שימוש אחר בקטגוריות: מסנן עקביות, שהעלה את הסט מ־22 ל־25 מתוך 27.

### הצעה של Claude ששיניתי

בהתחלה Claude המליץ לטעון את הקטלוג בפקודה ייעודית ולא בסידר, כדי שיהיה אפשר להריץ אותה שוב בפרודקשן. בחרתי בסידר, כי הוא מוכר ופשוט להסביר. את הבעיה שהוא הצביע עליה פתרתי בכך שהסידר מעדכן לפי מק"ט, וטסט מוודא שהרצה חוזרת לא משכפלת שורות. אם הקטלוג יתעדכן באופן שוטף, אעבור לפקודה ייעודית.

### הצעות שנדחו אחרי בדיקה

התכנון הראשוני נעשה עם Gemini, ו־Claude עזר לבדוק אותו:

- **שיטת הבקשה SEARCH, עם ציטוט של תקן:** התקן שצוטט עוסק במשהו אחר לגמרי. השיטה הרלוונטית נקראת QUERY, והיא עדיין טיוטה. חלק מהשרתים והמטמונים לא מכירים אותה, ואי אפשר לשתף קישור לחיפוש. נבחרה בקשת קריאה רגילה.
- **אירוח בוורסל עם פוסטגרס:** ורסל מריץ פי־אייץ'־פי רק דרך הרחבה של הקהילה, וגם העדפתי מייסקיואל.
- **"ניקוי" קלט מפני הזרקת סקריפטים:** העיקרון הנכון הוא קידוד בזמן ההצגה. התבניות עושות את זה כברירת מחדל, וטסט מוודא שתגית סקריפט חוזרת כטקסט.

### מקרים שבהם Claude עצר לפני שהמשיך

- **לפני הכיול:** Claude ניתח כל ערוץ בנפרד, ונתן לי לבחור בין מודל גדול יותר, ניסוח מחדש במודל שפה, או לקבל את המצב ולתעד אותו. בחרתי לנסות קודם את המודל הגדול, בניסוי הוגן.
- **אחרי הפריסה הראשונה:** היא הסתיימה מהר מדי. מכיוון שהסימון בפקודת הווקטורים מסתיר כישלון, Claude קרא את הלוג ווידא שכל הווקטורים חושבו.

### באגים שנתפסו

- **התנגשות שמות:** עמודת התכונות מהקובץ התנגשה במערך הפנימי של אלוקוונט שנקרא באותו שם. השם שלה שונה לפני הפריסה.
- **חתימת הווקטורים בלי המודל:** החלפת מודל הייתה משאירה וקטורים ישנים. התיקון כולל טסט.
- **באג שנמצא רק בדפדפן:** קריאה קרה לאופן־איי חרגה ממגבלת הזמן של 2 שניות. הגיבוי עבד, אבל הממשק הציג "לא נמצאו מוצרים" בחיפוש "מתנה למישהו שאוהב לבשל". התיקון: מגבלת זמן של 3 שניות, ושדה גיבוי בתשובה עם הודעה כנה בממשק.

## מגבלות ידועות ושיפורים להמשך

### מגבלות

- **כוונה שדורשת ידע עולם:**
  - **שערות כלב מהספה:** החיפוש עובר את סט הזהב, עם מברשת הסרת שיער ושוטף שטיחים לבתים עם חיות. אבל השואבים, שהם התשובה הטבעית, מופיעים רק במקום 16. ערוץ המשמעות מדרג אותם בין המקומות 49 ל־128 מתוך 1000, כי הוא לא "יודע" ששערות על ספה מנקים בשואב.
  - **מתנה לאמא טריה:** החיפוש מחזיר מוצרים לאמא, אבל לא לתינוק.
- **כתיב חסר דו־משמעי בעברית:** "סכינים" ו"מסוכנים" מקבלים את אותו שלד, ולכן השלד משמש רק כגיבוי. חיפוש שבו מילה אחת מופיעה בקטלוג בכתיב אחר, ומילה אחרת מופיעה כפי שנכתבה, עלול לפספס.
- **תמונות:** כל 1000 התמונות בקטלוג שסופק הן תמונות זמניות, עם שם סוג המוצר באנגלית. הממשק מציג אותן כמו שהן, ותמונה שלא נטענת מוחלפת ברקע ניטרלי.
- **מסנן העקביות:** בחיפוש של מותג מופיעים, אחרי תוצאות המותג, גם מוצרים אחרים מאותה תת־קטגוריה, למשל שואבים של יצרנים אחרים אחרי דייסון. זו בחירה מודעת, כדי לא להציג מוצר בודד.
- **מחירי המחשה:** הם לא תמיד הגיוניים בתוך אותה תת־קטגוריה. למשל, דגם הפרו עשוי לצאת זול מהקומפקטי.
- **הסף לא מבחין בין "לא קיים" לבין "קיים חלקית":** "כרטיס טיסה לאילת" מחזיר אביזרי נסיעה עם הודעה, ולא מסך ריק. זו הייתה החלטה מוצרית.
- **חישוב הקרבה בזיכרון:** מתאים לאלפי מוצרים. בעשרות אלפים צריך אינדקס וקטורי ייעודי.
- **זמני תגובה:** שאילתה חדשה תלויה בזמן התגובה של אופן־איי, והשינה של השרת כשאין תנועה מוסיפה זמן התעוררות לחיפוש הראשון.
- **מיקום השרת:** במזרח ארצות הברית, כלומר כרבע שנייה של רשת מישראל. מצד שני, הוא קרוב יותר לאופן־איי.

### מה הייתי עושה עם עוד זמן

- **ניסוח מחדש במודל שפה, רק לשאילתות ארוכות:** עם מטמון וגיבוי. המודל יתרגם "משהו שיעזור לנקות שערות של כלב מהספה" ל"שואב אבק ידני, מברשת שיער לחיות". זה הכלי הנכון לכוונה שדורשת ידע עולם, והוא נדחה כרגע רק בגלל הזמן.
- **מצב "מילות מפתח בלבד", רעיון שלי:** מתג בממשק לחיפוש מדויק של המילים במסד, בלי ערוץ המשמעות, למי שיודע בדיוק מה הוא מחפש, כמו שם דגם או מק"ט. המנוע כבר תומך בזה, ונשאר לחשוף את זה כפרמטר בבקשה וכמתג בממשק.
- **מסך תיוג לבודק פנימי, רעיון שלי:** עובד חברה מסמן תוצאות חיפוש בסולם קבוע: לא רלוונטי, רלוונטי חלקית או רלוונטי. התיוגים נשמרים בטבלה, וכל לילה רצה משימה מתוזמנת שמשתמשת בהם בארבע רמות, מהפשוטה לכבדה:
  - **הרחבה של סט הזהב:** כל תיוג הופך לשורה בסט. עם 30 שאילתות קל מדי להתאים את הספים יותר מדי לסט עצמו, ועם מאות שאילתות זה כבר מדד אמין.
  - **כיול אוטומטי:** אותו חיפוש רשת על הסף ועל המרווח שעשינו ידנית, רק על התיוגים.
  - **כללים לשאילתה מסוימת:** תיוג "לא רלוונטי" מוריד מוצר מהשאילתה, ותיוג "רלוונטי" מעלה אותו. לכל כלל יש תאריך תפוגה, כי הקטלוג משתנה.
  - **מדרג קטן משלנו:** עם כמה מאות תיוגים אפשר לאמן מודל פשוט שלומד כמה משקל לתת לכל אות: דמיון במשמעות, התאמה במילים, השדה שבו הייתה ההתאמה והתאמה לתת־הקטגוריה. זה כוונון על המסד הזה במובן הנכון.
  - **מה התיוג לא עושה:** הוא לא מאמן את מודל הווקטורים עצמו, כי זה שירות חיצוני וסגור.
  - **סיכונים:** בלי הנחיות ברורות, שני בודקים יתייגו אחרת. בודק רואה רק את מה שהחיפוש כבר החזיר, ולכן כדאי לשלב מדי פעם תוצאות מעמודים מאוחרים. את השאילתות לתיוג בוחרים מתוך הלוג: קודם הנפוצות, ואלה שהחזירו אפס תוצאות.
  - **למה זה לא בקוד:** המשימה הגדירה במפורש שאין צורך בממשק ניהול.
- **פילטרים:** קטגוריה, מותג וטווח מחיר, מעל אותה נקודת חיפוש, כשיגיעו מחירים אמיתיים.
- **הרחבה של סט הזהב:** משאילתות אמיתיות מתוך הלוג שכבר נרשם לכל חיפוש, ובדיקה אוטומטית שמריצה אותו ונכשלת כשהתוצאה יורדת.
- **חימום של מטמון השאילתות:** לחיפושים הנפוצים, ומטמון ייעודי במקום המטמון שבמסד.
- **ייבוא מתוזמן של הקטלוג:** אם יתברר שהוא מתעדכן. השאלה הועברה למור.

## שאלות פתוחות

שתי השאלות נשלחו במייל לאורנית, שהעבירה אותן למור, ועדיין אין תשובה. הפירוט נמצא בקובץ השאלות הפתוחות:

- **גידול הקטלוג:** האם צפוי ייבוא חוזר, או עשרות אלפי מוצרים? בינתיים יש סידר שמעדכן לפי מק"ט, וחישוב בזיכרון.
