חיפוש בעברית ובאנגלית, גם לפי שם המוצר וגם לפי תיאור של צורך, על הקטלוג של 1000 המוצרים שסופק.

- **אתר חי:** https://htzone-search-production-3qvz8h.laravel.cloud
- **API:** [`GET /api/search?q=אייפון&page=1`](https://htzone-search-production-3qvz8h.laravel.cloud/api/search?q=%D7%90%D7%99%D7%99%D7%A4%D7%95%D7%9F)
- **מסמכי עבודה:** [החלטות ארכיטקטורה](docs/decisions.md) · [יומן העבודה עם Claude](docs/claude-log.md) · [שאלות פתוחות](docs/open-questions.md) · [סט הזהב](tests/golden/queries.json)

| | |
|---|---|
| **Stack** | Laravel 13 (PHP 8.5), MySQL 8.4, Blade + Alpine.js + Tailwind v4, OpenAI `text-embedding-3-large` |
| **רלוונטיות** | 27 מתוך 28 חיפושים בסט הזהב (מילים בלבד: 18/28) |

## 1. הוראות הרצה וטעינת הקטלוג

**דרישות:** Docker, PHP 8.3+, Composer, Node 20+, ומפתח OpenAI. בלי מפתח, החיפוש עובד לפי מילים בלבד.

```bash
git clone https://github.com/amir-1004/htzone-search.git && cd htzone-search
composer install
cp .env.example .env                       # ולהוסיף OPENAI_API_KEY=...
./vendor/bin/sail up -d                    # MySQL 8.4 + phpMyAdmin (localhost:8080)
./vendor/bin/sail artisan key:generate
./vendor/bin/sail artisan migrate --seed   # טעינת הקטלוג מ-data/catalog.csv
./vendor/bin/sail artisan catalog:embed    # וקטורי משמעות לכל מוצר (כ-2 סנט, 1-2 דקות)
npm install && npm run build
```

האתר זמין בכתובת http://localhost.

### טעינת הקטלוג

- **`CatalogSeeder`** קורא את `data/catalog.csv` ומבצע upsert לפי מק"ט. אפשר להריץ אותו שוב בבטחה: אין שכפולים, ומוצר שהשתנה מתעדכן. כשחסרות עמודות ב-CSV, הסידר נכשל עם הודעה ברורה.
- **`php artisan catalog:embed`** מחשב וקטור משמעות רק למוצרים שהטקסט שלהם השתנה, או כשמודל הווקטורים הוחלף. הוא ממתין כשמגיעים למגבלת הקצב של OpenAI, ואם הספק נופל, החיפוש ממשיך לעבוד לפי מילים.
- **מחירים:** בקטלוג שסופק אין עמודת מחיר. לכל מוצר נקבע מחיר המחשה קבוע בטווח שמתאים לתת-הקטגוריה שלו (`config/catalog.php`), והממשק מציין שהמחירים להמחשה. שאלתי על זה את מור במייל.

### פריסה (Laravel Cloud)

כל ההגדרה נעשתה דרך ה-CLI הרשמי, כך שאפשר לשחזר אותה:

```bash
composer global require laravel/cloud-cli && cloud auth
cloud deploy htzone-search production
```

| שלב | פקודות |
|---|---|
| Build | `composer install --no-dev` → `npm ci` → `npm run build` → `php artisan optimize` |
| Deploy | `php artisan migrate --force` → `php artisan db:seed --force` → `php artisan catalog:embed \|\| true` |
| משתנים | `OPENAI_API_KEY` ו-`APP_LOCALE=he`. פרטי MySQL מוזרקים אוטומטית |

הסימון `|| true` נועד לכך שנפילה של OpenAI לא תכשיל את הפריסה. אין מפתחות או סיסמאות במאגר: `.env` לא נשמר בגיט, וההיסטוריה נסרקה לפני שהמאגר הפך לציבורי.

## 2. איך זה עובד

```
"משהו שיעזור לנקות שערות של כלב מהספה"
        │
        ├─ ערוץ מילים: נרמול (ניקוד, גרשיים, אותיות סופיות, תחיליות ו/ה/ב/ל, רבים, וכגיבוי: כתיב חסר טוחן=טחון) + מילון כינויים (אייפון → Apple סמארטפון)
        │      ↳ ציון לפי שדה (שם, מותג, קטגוריה, תיאור) ושיעור כיסוי של מילות השאילתה
        │
        ├─ ערוץ משמעות: וקטור לשאילתה (OpenAI, נשמר במטמון) מול 1000 וקטורים שחושבו מראש
        │      ↳ סף 0.30 + מרווח של 0.10 מהתוצאה הטובה ביותר (ותמיד לפחות 6 מעל הסף)
        │      ↳ מסנן עקביות: מוצר שנמצא רק לפי משמעות חייב להיות בתת-קטגוריה שהשאילתה עוסקת בה
        │
        └─ מיזוג Reciprocal Rank Fusion → עד 60 תוצאות → 12 בעמוד → JSON → Alpine
```

- **`app/Search/ProductSearch.php`:** המיזוג, הגיבוי כשהספק נופל, ומדידת זמנים לכל שלב.
- **`app/Search/KeywordRanker.php`, `TextNormalizer.php`:** ערוץ המילים.
- **`app/Search/SearchIndex.php`:** כל הקטלוג (טוקנים ווקטורים) נטען למטמון תחת מפתח גרסה, כך שאחרי שינוי במוצרים האינדקס נבנה מחדש.
- **`app/Http/Controllers/SearchController.php`:** ולידציה, עימוד, לוג לכל חיפוש, ו-`match`/`degraded` לממשק.
- **`resources/views/search.blade.php` + `resources/js/product-search.js`:** הממשק.

בתשובה יש שני שדות שהממשק נשען עליהם:

- **`match: "related"`:** אף תוצאה לא מכילה את מילות החיפוש, וכולן נמצאו לפי משמעות. הממשק מציג "לא מצאנו התאמה מדויקת, אלה המוצרים הקרובים". זה המצב, למשל, עבור "כרטיס טיסה לאילת" ועבור "iPhone 16", כי אין דגם 16 בקטלוג.
- **`degraded: true`:** החיפוש לפי משמעות היה אמור לרוץ, אבל הספק נכשל. הממשק מציג "החיפוש החכם לא זמין כרגע" ולא "לא נמצאו מוצרים".

## 3. החלטות מרכזיות

ההחלטות המלאות, עם המספרים, נמצאות ב-[docs/decisions.md](docs/decisions.md).

| החלטה | למה | מה נדחה |

| **שכבה סמנטית היא חובה** | בדקתי את הקטלוג לפני שכתבתי קוד: המילה iPhone לא מופיעה בו (הטלפונים רשומים כ"סמארטפון" עם מותג Apple). גם "פלייסטיישן" לא מופיע, ויש שגיאת כתיב בנתונים ("מטהג"). חיפוש מילים לבד נכשל ב-2 מתוך 5 הדוגמאות שבמשימה | חיפוש מילים בלבד (14/23 בסט הזהב) |
| **חיפוש משולב: וקטורים + מילים + מילון כינויים** | הווקטורים מבינים צורך, המילים מדויקות לשמות ולמותגים, והכינויים מכסים שמות שלא מופיעים בקטלוג. אם OpenAI נופל, החיפוש ממשיך לפי מילים | מודל שפה שמנסח מחדש כל שאילתה (שנייה נוספת ועלות על כל חיפוש), ו-MeiliSearch/Algolia (שירות נוסף, ועדיין לא מבין צורך) |
| **וקטורים בעמודה ב-MySQL, וחישוב הקרבה ב-PHP** | באלף מוצרים זה לוקח מילישניות. ב-MySQL community אין פונקציה למדידת מרחק בין וקטורים | שירות וקטורים חיצוני, או מעבר ל-Postgres + pgvector |
| **`text-embedding-3-large` ב-512 ממדים** | ניסוי הוגן מול המודל הקטן (אותם ממדים, רק המודל השתנה) הראה שהמודל הקטן לא מבין כוונה בעברית: אפילו "בישול" החזיר משקולות. הגדול מחזיר סירים עבור "מתנה לבשלן" | `text-embedding-3-small` |

| **ספים מכוילים מסט הזהב** | ג'יבריש מגיע לדמיון של 0.20 לכל היותר, וחיפוש אמיתי מתחיל ב-0.385. חיפוש רשת על 8 צירופים נתן תוצאה זהה לכל מרווח מ-0.08 ומעלה, ונבחר אמצע הטווח היציב | ערך שנבחר "בעין" |
| **Laravel + Blade + Alpine** | PHP הוא העדפה שלכם והמגרש שלי. עמוד אחד, בלי SPA ובלי שני שירותים לפרוס | React (תהליך בנייה נוסף ושפה שנייה בפרויקט) |
| **MySQL + Laravel Cloud** | הפלטפורמה הרשמית של הפריימוורק, עם MySQL מנוהל ו-scale-to-zero | Vercel + Postgres (שמריץ PHP רק דרך runtime של הקהילה) |
| **`GET /api/search?q=`** | אפשר לשתף קישור לחיפוש, כפתור "חזרה" עובד, ואפשר לשמור במטמון | HTTP `SEARCH`/`QUERY`, ראו סעיף 5 |
| **חיפוש בלחיצה, ו"הצגת מוצרים נוספים"** | חיפוש לפי משמעות עובד על משפט שלם, וכל הקלדה הייתה שולחת קריאה ל-OpenAI על מילה חלקית. "טען עוד" נוח בנייד, והדירוג נחלש ככל שיורדים ברשימה | חיפוש תוך כדי הקלדה, ומספרי עמודים |
| **מחירי המחשה, מסומנים** | הדרישה היא להציג מחיר, והקטלוג הגיע בלי מחירים. נשלחה שאלה, והעבודה לא נעצרה בינתיים | להציג "אין מחיר", או לעצור עד לתשובה |

### ב. טסטים אוטומטיים (Pest, 34 טסטים, על MySQL ולא על SQLite)

```bash
./vendor/bin/sail artisan test
```

- **קטלוג:** ייבוא של 1000 מוצרים, מותג חסר נשמר כ-null, הרצה חוזרת לא משכפלת, מחירים בטווח, CSV שחסרות בו עמודות נכשל בקול.
- **API:** מבנה התשובה, מילון הכינויים (אייפון), עימוד בלי חפיפה בין עמודים, שאילתה ריקה, ג'יבריש מחזיר 0 ולא "הכי קרוב", קלט של מעל 200 תווים מחזיר 422, ו-`<script>` נשאר טקסט.
- **נרמול עברית:** אותיות סופיות, תחיליות, רבים, וכתיב מלא מול חסר.
- **מסנן עקביות:** מוצר מתת-קטגוריה לא קשורה נשמט כשהמסנן פועל, ומופיע כשהוא כבוי.
- **שכבה סמנטית בלי מפתח אמיתי:** `Http::fake` מחזיר וקטורים מלאכותיים. נבדק שהדירוג לפי משמעות עובד, שנפילה של הספק עוברת למילים עם `degraded=true`, ש-`catalog:embed` לא שולח שוב מוצרים שלא השתנו, ושהחלפת מודל מחשבת את כל הקטלוג מחדש.
- **ממשק:** `lang="he" dir="rtl"`, וטסט שסורק את התבנית ומוודא שלכל מחרוזת יש תרגום ב-`lang/he.json`.

### ג. בדיקה בדפדפן, במחשב ובנייד (375px)

עברתי על כל המצבים: פתיחה, טעינה, תוצאות, "טען עוד" (12, אחר כך 24 מתוך 60), ריק, ושגיאת רשת מדומה. בבדיקה הזו נמצא באג שהטסטים לא תפסו (פירוט בסעיף 5). נמצאו גם ארבעה תיקוני RTL ונייד: הנקודה של הלוגו, מירכאות, כפתור בנייד, והודעת שגיאה באנגלית.

## 5. איך עבדתי עם Claude

עבדתי עם Claude Code (Opus 5.5). לפני כל שלב Claude ראיין אותי על ההחלטות, וכל החלטה עם השלכה על המוצר נשארה אצלי. את מה שהוא עשה, וידאתי באחת משלוש דרכים: טסט, סט הזהב, או בדיקה בדפדפן. [היומן המלא](docs/claude-log.md).

**איך העבודה הייתה מסודרת:**
- [`CLAUDE.md`](CLAUDE.md) מכיל את המוסכמות: אין טקסט בלי תרגום, אין מפתחות במאגר, `Http::fake` בכל טסט, ומעבר על סט הזהב אחרי כל שינוי במנוע.
- כל שלב (תכנון, בנייה, חיפוש, כיול, פריסה, ממשק) נשמר ב-commit נפרד, עם הודעה בעברית.
- את הפריסה Claude ביצע דרך ה-CLI של Laravel Cloud. את ההרשאה בדפדפן ואת הגדרת מפתח OpenAI עשיתי אני, ו-Claude לא ראה את המפתח.

**הצעה של Claude שנבדקה ונדחתה לפי מספרים:** שאלתי אם אפשר לשפר את החיפוש בעזרת הקטגוריות. Claude הציע לחזק מוצרים לפי וקטור ממוצע של תת-הקטגוריה. ביקשתי שיבדוק ולא ישמור אם זה לא משפר. השיפור היה 2 מוצרים רלוונטיים מתוך כל הסט, בלי אף כישלון שהפך להצלחה, ולכן הקוד הוסר. אחר כך בדקתי בעצמי כמה חיפושים ("סכינים", "שעון יד", "כלב גדול", "מתנה לאמא טריה") ומצאתי בהם רעש. Claude הוסיף אותם לסט הזהב ותכנן שימוש אחר בקטגוריות: מסנן עקביות, שהעלה את הסט מ-22 ל-25 מתוך 27.

**הצעה של Claude ששיניתי:** Claude המליץ לטעון את הקטלוג בפקודת artisan ייעודית ולא ב-Seeder, כדי שיהיה אפשר להריץ אותה שוב בפרודקשן. בחרתי ב-Seeder כי הוא מוכר ופשוט להסביר. את הבעיה שהוא הצביע עליה פתרתי בכך שהסידר עושה upsert לפי מק"ט, וטסט מוודא שהרצה חוזרת לא משכפלת שורות. אם הקטלוג יתעדכן באופן שוטף, אעבור לפקודה ייעודית.

**הצעות שנדחו אחרי בדיקה** (התכנון הראשוני נעשה עם Gemini, ו-Claude עזר לבדוק אותו):
- **HTTP `SEARCH` לנקודת הקצה, עם ציטוט של RFC 8141.** RFC 8141 עוסק ב-URN. השיטה הרלוונטית נקראת `QUERY`, והיא עדיין טיוטה. חלק מהפרוקסים והמטמונים לא מכירים אותה, ואי אפשר לשתף קישור לחיפוש. נבחר GET רגיל.
- **Vercel + Postgres.** Vercel מריץ PHP רק דרך runtime של הקהילה, וגם העדפתי MySQL.
- **"לנקות" קלט מפני XSS.** העיקרון הנכון הוא קידוד בפלט. Blade ו-`x-text` עושים את זה, וטסט מוודא ש-`<script>` חוזר כטקסט.

**מקרים שבהם Claude עצר לפני שהמשיך:**
- לפני שכייל ספים, Claude ניתח כל ערוץ בנפרד ונתן לי לבחור בין מודל גדול יותר, ניסוח מחדש במודל שפה, או לקבל את המצב ולתעד אותו. בחרתי לנסות קודם את המודל הגדול, בניסוי הוגן.
- הפריסה הראשונה הסתיימה "מהר מדי". מכיוון ש-`|| true` מסתיר כישלון, Claude קרא את הלוג ווידא שכל הווקטורים חושבו.

**באגים שנתפסו:**
- **התנגשות שמות:** העמודה `attributes` מה-CSV מתנגשת ב-`$attributes` הפנימי של Eloquent. שמה שונה ל-`specs` לפני הפריסה.
- **hash של וקטורים בלי המודל:** החלפת מודל הייתה משאירה וקטורים ישנים. נוסף טסט.
- **באג שנמצא רק בדפדפן:** קריאה קרה ל-OpenAI חרגה ממגבלת הזמן של 2 שניות. הגיבוי עבד, אבל הממשק הציג "לא נמצאו מוצרים" עבור "מתנה למישהו שאוהב לבשל". התיקון: מגבלת זמן של 3 שניות, ושדה `degraded` עם הודעה כנה בממשק.

## 6. מגבלות ידועות ושיפורים להמשך

**מגבלות:**
- **כוונה שדורשת ידע עולם:**
  - "שערות כלב מהספה" עובר את סט הזהב: מברשת הסרת שיער ושוטף שטיחים לבתים עם חיות. אבל השואבים, שהם התשובה הטבעית, מופיעים רק במקום 16. ערוץ המשמעות מדרג אותם במקומות 49-128 מתוך 1000, כי הוא לא "יודע" ששערות על ספה מנקים בשואב.
  - "מתנה לאמא טריה" מחזירה מוצרים לאמא, אבל לא לתינוק.
- **כתיב חסר דו-משמעי בעברית:** "סכינים" ו"מסוכנים" מקבלים אותו שלד, ולכן השלד משמש רק כגיבוי. חיפוש שבו המילה מופיעה בקטלוג בכתיב אחר, וגם מילה אחרת בשאילתה מופיעה כפי שנכתבה, עלול לפספס.
- **תמונות:** כל 1000 התמונות בקטלוג שסופק הן placeholders של `placehold.co`, עם שם סוג המוצר באנגלית. הממשק מציג אותן כמו שהן, ותמונה שלא נטענת מוחלפת ברקע ניטרלי.
- **מסנן העקביות:** בחיפוש מותג מופיעים אחרי תוצאות המותג גם מוצרים אחרים מאותה תת-קטגוריה (שואבים אחרים אחרי Dyson). זו הבחירה המודעת שעשיתי, כדי לא להציג מוצר בודד.
- **מחירי המחשה:** לא תמיד הגיוניים בתוך אותה תת-קטגוריה. למשל, ה-Pro עשוי לצאת זול מהקומפקטי.
- **הסף לא מבחין בין "לא קיים" ל"קיים חלקית":** "כרטיס טיסה לאילת" מחזיר אביזרי נסיעה עם הודעה, ולא מסך ריק. זו הייתה החלטה מוצרית.
- **חישוב הקרבה בזיכרון:** מתאים לאלפי מוצרים. בעשרות אלפים צריך אינדקס וקטורי ייעודי (pgvector, Qdrant, או Vector Search של MySQL HeatWave).
- **זמני תגובה:** שאילתה חדשה תלויה בזמן התגובה של OpenAI, ו-scale-to-zero מוסיף התעוררות לחיפוש הראשון אחרי זמן בלי שימוש.
- **האזור:** השרת ב-us-east-1, כלומר כ-250ms רשת מישראל. הוא קרוב יותר ל-OpenAI.

**מה הייתי עושה עם עוד זמן:**
1. **ניסוח מחדש במודל שפה, רק לשאילתות ארוכות** (Claude Haiku או מודל קטן של OpenAI), עם מטמון וגיבוי. המודל יתרגם "משהו שיעזור לנקות שערות של כלב מהספה" ל"שואב אבק ידני, מברשת שיער לחיות". זה הכלי הנכון לכוונה שדורשת ידע עולם, והוא נדחה כרגע רק בגלל הזמן.
2. **מצב "מילות מפתח בלבד"** (רעיון שלי): מתג בממשק לחיפוש מדויק של המילים במסד, למי שיודע בדיוק מה הוא מחפש (שם דגם, מק"ט). המנוע כבר תומך בזה (`useVectors: false`), ונשאר לחשוף את זה כפרמטר ב-API ומתג בממשק.
3. **פילטרים** (קטגוריה, מותג, טווח מחיר) מעל אותו API, כשיגיעו מחירים אמיתיים.
4. **הרחבה של סט הזהב** משאילתות אמיתיות, מתוך הלוג שכבר נרשם לכל חיפוש, ו-CI שמריץ אותו ונכשל בירידה.
5. **חימום של מטמון השאילתות** לחיפושים הנפוצים, ו-Valkey במקום מטמון במסד.
6. **ייבוא מתוזמן** של הקטלוג, אם יתברר שהוא מתעדכן. השאלה נשלחה למור.
