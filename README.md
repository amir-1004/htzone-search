| | |
|---|---|
| **Stack** | Laravel 13 (PHP 8.5), MySQL 8.4, Blade + Alpine.js + Tailwind v4, OpenAI `text-embedding-3-large` |
| **רלוונטיות** | 21 מתוך 23 חיפושים בסט הזהב (מילים בלבד: 14/23) |

## 1. הוראות הרצה וטעינת הקטלוג

**דרישות:** Docker, PHP 8.3+, Composer, Node 20+, ומפתח OpenAI. בלי מפתח, החיפוש עובד לפי מילים בלבד.

```bash
git clone https://github.com/amir-1004/htzone-search.git && cd htzone-search
composer install
cp .env.example .env                       # ולהוסיף OPENAI_API_KEY=...
./vendor/bin/sail up -d                    # MySQL 8.4 + phpMyAdmin (localhost:8080)
./vendor/bin/sail artisan key:generate
./vendor/bin/sail artisan migrate --seed   # טעינת הקטלוג מ-data/catalog.csv
./vendor/bin/sail artisan catalog:embed    # וקטורי משמעות לכל מוצר (כ-2 סנט, 1-2 דקות)
npm install && npm run build
```

האתר זמין בכתובת http://localhost.

### טעינת הקטלוג

- **`CatalogSeeder`** קורא את `data/catalog.csv` ומבצע upsert לפי מק"ט. אפשר להריץ אותו שוב בבטחה: אין שכפולים, ומוצר שהשתנה מתעדכן. כשחסרות עמודות ב-CSV, הסידר נכשל עם הודעה ברורה.
- **`php artisan catalog:embed`** מחשב וקטור משמעות רק למוצרים שהטקסט שלהם השתנה, או כשמודל הווקטורים הוחלף. הוא ממתין כשמגיעים למגבלת הקצב של OpenAI, ואם הספק נופל, החיפוש ממשיך לעבוד לפי מילים.
- **מחירים:** בקטלוג שסופק אין עמודת מחיר. לכל מוצר נקבע מחיר המחשה קבוע בטווח שמתאים לתת-הקטגוריה שלו (`config/catalog.php`), והממשק מציין שהמחירים להמחשה. שאלתי על זה את מור במייל.

### פריסה (Laravel Cloud)

כל ההגדרה נעשתה דרך ה-CLI הרשמי, כך שאפשר לשחזר אותה:

```bash
composer global require laravel/cloud-cli && cloud auth
cloud deploy htzone-search production
```

| שלב | פקודות |
|---|---|
| Build | `composer install --no-dev` → `npm ci` → `npm run build` → `php artisan optimize` |
| Deploy | `php artisan migrate --force` → `php artisan db:seed --force` → `php artisan catalog:embed \|\| true` |
| משתנים | `OPENAI_API_KEY` ו-`APP_LOCALE=he`. פרטי MySQL מוזרקים אוטומטית |

הסימון `|| true` נועד לכך שנפילה של OpenAI לא תכשיל את הפריסה. אין מפתחות או סיסמאות במאגר: `.env` לא נשמר בגיט, וההיסטוריה נסרקה לפני שהמאגר הפך לציבורי.

## 2. איך זה עובד

```
"משהו שיעזור לנקות שערות של כלב מהספה"
        │
        ├─ ערוץ מילים: נרמול (ניקוד, גרשיים, תחיליות ו/ה/ב/ל, רבים) + מילון כינויים (אייפון → Apple סמארטפון)
        │      ↳ ציון לפי שדה (שם, מותג, קטגוריה, תיאור) ושיעור כיסוי של מילות השאילתה
        │
        ├─ ערוץ משמעות: וקטור לשאילתה (OpenAI, נשמר במטמון) מול 1000 וקטורים שחושבו מראש
        │      ↳ סף 0.30 + מרווח של 0.10 מהתוצאה הטובה ביותר
        │
        └─ מיזוג Reciprocal Rank Fusion → עד 60 תוצאות → 12 בעמוד → JSON → Alpine
```

- **`app/Search/ProductSearch.php`:** המיזוג, הגיבוי כשהספק נופל, ומדידת זמנים לכל שלב.
- **`app/Search/KeywordRanker.php`, `TextNormalizer.php`:** ערוץ המילים.
- **`app/Search/SearchIndex.php`:** כל הקטלוג (טוקנים ווקטורים) נטען למטמון תחת מפתח גרסה, כך שאחרי שינוי במוצרים האינדקס נבנה מחדש.
- **`app/Http/Controllers/SearchController.php`:** ולידציה, עימוד, לוג לכל חיפוש, ו-`match`/`degraded` לממשק.
- **`resources/views/search.blade.php` + `resources/js/product-search.js`:** הממשק.

בתשובה יש שני שדות שהממשק נשען עליהם:

- **`match: "related"`:** אף תוצאה לא מכילה את מילות החיפוש, וכולן נמצאו לפי משמעות. הממשק מציג "לא מצאנו התאמה מדויקת, אלה המוצרים הקרובים". זה המצב, למשל, עבור "כרטיס טיסה לאילת" ועבור "iPhone 16", כי אין דגם 16 בקטלוג.
- **`degraded: true`:** החיפוש לפי משמעות היה אמור לרוץ, אבל הספק נכשל. הממשק מציג "החיפוש החכם לא זמין כרגע" ולא "לא נמצאו מוצרים".

## 5. איך עבדתי עם Claude

עבדתי עם Claude Code (Opus 5.5). לפני כל שלב Claude ראיין אותי על ההחלטות, וכל החלטה עם השלכה על המוצר נשארה אצלי. את מה שהוא עשה, וידאתי באחת משלוש דרכים: טסט, סט הזהב, או בדיקה בדפדפן. [היומן המלא](docs/claude-log.md).

**איך העבודה הייתה מסודרת:**
- [`CLAUDE.md`](CLAUDE.md) מכיל את המוסכמות: אין טקסט בלי תרגום, אין מפתחות במאגר, `Http::fake` בכל טסט, ומעבר על סט הזהב אחרי כל שינוי במנוע.
- כל שלב (תכנון, בנייה, חיפוש, כיול, פריסה, ממשק) נשמר ב-commit נפרד, עם הודעה בעברית.
- את הפריסה Claude ביצע דרך ה-CLI של Laravel Cloud. את ההרשאה בדפדפן ואת הגדרת מפתח OpenAI עשיתי אני, ו-Claude לא ראה את המפתח.

**הצעה של Claude ששיניתי:** Claude המליץ לטעון את הקטלוג בפקודת artisan ייעודית ולא ב-Seeder, כדי שיהיה אפשר להריץ אותה שוב בפרודקשן. בחרתי ב-Seeder כי הוא מוכר ופשוט להסביר. את הבעיה שהוא הצביע עליה פתרתי בכך שהסידר עושה upsert לפי מק"ט, וטסט מוודא שהרצה חוזרת לא משכפלת שורות. אם הקטלוג יתעדכן באופן שוטף, אעבור לפקודה ייעודית.

**הצעות שנדחו אחרי בדיקה** (התכנון הראשוני נעשה עם Gemini, ו-Claude עזר לבדוק אותו):
- **HTTP `SEARCH` לנקודת הקצה, עם ציטוט של RFC 8141.** RFC 8141 עוסק ב-URN. השיטה הרלוונטית נקראת `QUERY`, והיא עדיין טיוטה. חלק מהפרוקסים והמטמונים לא מכירים אותה, ואי אפשר לשתף קישור לחיפוש. נבחר GET רגיל.
- **Vercel + Postgres.** Vercel מריץ PHP רק דרך runtime של הקהילה, וגם העדפתי MySQL.
- **"לנקות" קלט מפני XSS.** העיקרון הנכון הוא קידוד בפלט. Blade ו-`x-text` עושים את זה, וטסט מוודא ש-`<script>` חוזר כטקסט.

**מקרים שבהם Claude עצר לפני שהמשיך:**
- לפני שכייל ספים, Claude ניתח כל ערוץ בנפרד ונתן לי לבחור בין מודל גדול יותר, ניסוח מחדש במודל שפה, או לקבל את המצב ולתעד אותו. בחרתי לנסות קודם את המודל הגדול, בניסוי הוגן.
- הפריסה הראשונה הסתיימה "מהר מדי". מכיוון ש-`|| true` מסתיר כישלון, Claude קרא את הלוג ווידא שכל הווקטורים חושבו.

**באגים שנתפסו:**
- **התנגשות שמות:** העמודה `attributes` מה-CSV מתנגשת ב-`$attributes` הפנימי של Eloquent. שמה שונה ל-`specs` לפני הפריסה.
- **hash של וקטורים בלי המודל:** החלפת מודל הייתה משאירה וקטורים ישנים. נוסף טסט.
- **באג שנמצא רק בדפדפן:** קריאה קרה ל-OpenAI חרגה ממגבלת הזמן של 2 שניות. הגיבוי עבד, אבל הממשק הציג "לא נמצאו מוצרים" עבור "מתנה למישהו שאוהב לבשל". התיקון: מגבלת זמן של 3 שניות, ושדה `degraded` עם הודעה כנה בממשק.

## 6. מגבלות ידועות ושיפורים להמשך

**מגבלות:**
- **שתי שאילתות כוונה עדיין חלשות:** "שערות כלב מהספה", שבה התוצאה הראשונה רלוונטית ואחריה מגיעים מוצרי כלבים כלליים, ו"מתנה ללידה", שהיא דו-משמעית.
- **מחירי המחשה:** לא תמיד הגיוניים בתוך אותה תת-קטגוריה. למשל, ה-Pro עשוי לצאת זול מהקומפקטי.
- **הסף לא מבחין בין "לא קיים" ל"קיים חלקית":** "כרטיס טיסה לאילת" מחזיר אביזרי נסיעה עם הודעה, ולא מסך ריק. זו הייתה החלטה מוצרית.
- **חישוב הקרבה בזיכרון:** מתאים לאלפי מוצרים. בעשרות אלפים צריך אינדקס וקטורי ייעודי (pgvector, Qdrant, או Vector Search של MySQL HeatWave).
- **זמני תגובה:** שאילתה חדשה תלויה בזמן התגובה של OpenAI, ו-scale-to-zero מוסיף התעוררות לחיפוש הראשון אחרי זמן בלי שימוש.
- **האזור:** השרת ב-us-east-1, כלומר כ-250ms רשת מישראל. הוא קרוב יותר ל-OpenAI.

**מה הייתי עושה עם עוד זמן:**
1. **ניסוח מחדש במודל שפה, רק לשאילתות ארוכות** (Claude Haiku), עם מטמון וגיבוי. זה הכלי הנכון לשתי שאילתות הכוונה שנכשלות.
2. **פילטרים** (קטגוריה, מותג, טווח מחיר) מעל אותו API, כשיגיעו מחירים אמיתיים.
3. **הרחבה של סט הזהב** משאילתות אמיתיות, מתוך הלוג שכבר נרשם לכל חיפוש, ו-CI שמריץ אותו ונכשל בירידה.
4. **חימום של מטמון השאילתות** לחיפושים הנפוצים, ו-Valkey במקום מטמון במסד.
5. **ייבוא מתוזמן** של הקטלוג, אם יתברר שהוא מתעדכן. השאלה נשלחה למור.
